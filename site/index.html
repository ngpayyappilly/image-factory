ImageFactory
How it works Status Contribute GitHub

Build the image once. Prove it. Sign it. Promote that exact artifact.

ImageFactory is an open-source golden-image pipeline driven entirely from Git. One Packer build and one set of hardening produce a CIS-hardened image per OS flavor; blocking gates decide whether it ships, and a signed manifest records exactly what it is. Rolling back means repointing a channel, never rebuilding.

Principles

Build once, promote the artifact

Promotion only repoints a channel; it never builds. Images and signed manifests are immutable.

Gates fail closed

Missing evidence is unmet, unparseable evidence is a failure, a test run with zero tests is a failure. Exceptions are time-boxed and approved.

One writer per object

Parallel builds each write only their own record; one release step writes the manifest; channel changes take a lock.

Cloud-neutral state

Manifests and channel pointers live in a store. Each cloud only projects them: SSM parameters, gallery tags, Secret Manager.

Architecture is part of the flavor

al2023 and al2023arm are different flavors, so there is never an ambiguous "latest".

No secrets in images or logs

Short-lived OIDC credentials, pinned and checksum-verified tools, and signatures that stay out of the public transparency log.

Help build it

You do not need a cloud account to start; most of the project is testable offline.

git clone https://github.com/ngpayyappilly/image-factory && cd image-factory
make setup && make check
  • Run RHEL 9, Ubuntu and Graviton builds for real and report what breaks. The most valuable contribution right now.
  • Run the Azure and GCP paths against your own subscription or project.
  • Write the VMware runtime plugin.
  • Build a tested Windows hardening baseline.
  • Decide CIS Level 1 versus Level 1 + 2 remediation.
